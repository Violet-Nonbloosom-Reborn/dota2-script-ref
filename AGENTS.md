# AGENTS.md

## Package Manager

Use **pnpm** (not npm). The `pnpm-workspace.yaml` configures build script approvals.

## Commands

```bash
pnpm install              # Install dependencies
pnpm run build            # Full build: clean → extract → process-dump
pnpm run build:extract    # Extract from Dota 2 VPKs (requires local Dota 2 install)
pnpm run build:process-dump # Process dumper/dump file only (no Dota 2 needed)
pnpm run auto-dump        # Launch Dota 2 and dump API (requires Dota 2 + tools)
pnpm run test             # Jest tests
pnpm run lint             # ESLint + Prettier check
pnpm run fix:prettier     # Auto-fix formatting
```

## Project Structure

| Directory | Purpose |
|-----------|---------|
| `dumper/` | Lua scripts + TS launcher that dumps Dota 2 API via vConsole |
| `dumper/dump` | Raw dump output (git-tracked, MediaWiki table format) |
| `build/` | TypeScript scripts that parse dump → structured JSON |
| `skills/` | Agent Skill definition and generated reference files |
| `skills/reference/` | Generated JSON reference files (git-ignored) |
| `test/` | Jest tests |

## Dump Format

The `dumper/dump` file contains multiple sections, each started by `$> command_name`:

| Section | Format | Content |
|---------|--------|---------|
| `dump_panorama_css_properties` | Custom text | Panorama CSS properties |
| `dump_panorama_events` | MediaWiki table | Panorama custom events |
| `cl_panorama_script_help_2` | MediaWiki table | Panorama enums + API classes (with params, no return types) |
| `cl_panorama_typescript_declarations` | TypeScript interface | Panorama API return types (supplement) |
| `script_reload` | JSON | VScripts Lua API (server) |
| `cl_script_reload` | JSON | VScripts Lua API (client) |

### MediaWiki Table Format

```
=== ClassName ===
{| class="standard-table"
! Function ! Signature ! Description
|-
| MethodName | <code>Class.Method( type arg )</code> | Description |
|}
```

For enums:
```
=== EnumName ===
{| class="standard-table"
! Enumerator ! Value ! Description
|-
| EnumName.MemberName | 0 | Description |
|}
```

## Build Flow

1. `build:extract` — Reads VPK files from Dota 2 install, generates events/enums
2. `build:process-dump` — Parses `dumper/dump`, generates `skills/reference/**/*.json`
3. Both scripts automatically update `skills/SKILL.md` version from dump's `ClientVersion`

For skill generation, only `build:process-dump` is needed (no VPK access).

## Panorama API Generation

The Panorama API is generated by merging two data sources:

1. **Primary**: `cl_panorama_script_help_2` — provides class list, method names, parameters
2. **Supplement**: `cl_panorama_typescript_declarations` — provides return types

Classes not found in `typescript_declarations` will have `returns: "any"`.

## Supplement Overrides

The dump does not provide complete descriptions or accurate parameter types for all functions.
Overrides are hardcoded in TypeScript files under `build/`. There are 5 files containing override data.

### Files

| File | Data | Purpose |
|------|------|---------|
| `build/vscripts/api/data/index.ts` | `classExtensions` | Add new members to existing classes |
| `build/vscripts/api/data/index.ts` | `functionExtensions` | Override function descriptions, return types, and parameter types/names |
| `build/vscripts/api/data/index.ts` | `extraDeclarations` | Add entirely new classes/functions not in the dump (Vector, QAngle, Uint64, etc.) |
| `build/vscripts/api/data/moddota-dump.ts` | `moddotaDump` | Community-contributed overrides (spread into `functionExtensions`) |
| `build/vscripts/api/data/modifier-properties.ts` | `modifiersData` | Modifier function signatures (argument event type, return type, description) |
| `build/vscripts/enums/data.ts` | `enumValueDescriptions` | Descriptions for specific enum values |
| `build/panorama/events/data.ts` | `additions`, `override` | Panorama event additions and argument overrides |

Note: `build/vscripts/api-types/index.ts` defines `apiTypesDeclarations` which generates `api-types.json`. This is not an override mechanism — all type definitions (primitives, nominals, objects) are manually authored from scratch and do not correspond to any dump data.

### Key Types (defined in `build/vscripts/api/data/utils.ts`)

```typescript
interface ExtensionFunction {
  deprecated?: string;
  description?: string | ((original?: string) => string);
  returns?: _.Many<Type>;
  args?: Record<number, [string | null, (Many<Type> | null)?, string?]>;
}

interface ExtensionClass {
  description?: string;
  members?: ClassMember[];
}
```

### How to Add Function Overrides

Key format is `"ClassName.MethodName"` or `"_G.FunctionName"` for globals.

```typescript
// In build/vscripts/api/data/index.ts → functionExtensions
'CDOTA_BaseNPC_Hero.SomeMethod': {
  description: 'Replaces the original description entirely.',
},

'CDOTA_BaseNPC_Hero.AnotherMethod': {
  description: (original) => `${original} Appended note.`,  // Transform original
},

'CDOTA_BaseNPC_Hero.ThirdMethod': {
  description: '',  // Empty string removes the description
  returns: 'CDOTA_BaseNPC',  // Override return type
  args: {
    0: ['argName', 'TypeName'],           // Override name + type
    1: [null, 'TypeName'],                // Keep original name, override type
    2: ['argName', null],                 // Override name, keep original type
    3: ['argName', 'TypeName', 'Per-argument description'],  // With arg description
    4: ['arg', ['Type1', 'Type2']],       // Multiple types (union)
    5: ['arg', ['Type', 'nil']],          // Nullable type
  },
},
```

### Type Helper Functions (from `utils.ts`)

Use these when you need complex types in overrides:

```typescript
literal(0)                              // Literal numeric type
binaryBoolean                           // Shorthand for [literal(0), literal(1)]
array('CDOTA_BaseNPC')                  // Array type: CDOTA_BaseNPC[]
func([['unit', 'CDOTA_BaseNPC']], 'nil') // Function type: (unit: CDOTA_BaseNPC) => nil
```

### Dynamic Description Patterns

Some overrides use shared variables or functions. These exist in `moddota-dump.ts`:

```typescript
// Shared description variable (reused across multiple functions)
const createUnitByNameDescription = `Creates a unit by its dota_npc_units.txt name. ...`;

'_G.CreateUnitByName': {
  description: `${createUnitByNameDescription}\nWarning: mass synchronous ...`,
},
'_G.CreateUnitByNameAsync': {
  description: createUnitByNameDescription,
},

// Function that appends to the original description
const setOwnerDescription = 'This entity will be returned by GetOwner()...';

'CBaseEntity.SetOwner': {
  description: (o) => `${o} ${setOwnerDescription}`,
},
```

### How to Add Class Members

```typescript
// In build/vscripts/api/data/index.ts → classExtensions
CBaseEntity: {
  members: [
    {
      kind: 'function',
      name: 'NewMethod',
      available: 'both',       // 'server' | 'client' | 'both'
      description: 'Does something.',
      returns: ['bool'],
      args: [{ name: 'target', types: ['CDOTA_BaseNPC'] }],
    },
  ],
},
```

### How to Add Modifier Properties

In `build/vscripts/api/data/modifier-properties.ts` → `modifiersData`:

```typescript
// [ArgumentEventType | null, ReturnType[], Description?]
GetModifierAttackSpeedBonus_Constant: [null, ['float']],
GetModifierAvoidDamage: ['ModifierAttackEvent', ['float']],
GetModifierHealthBarPips: ['ModifierAttackEvent', ['float'], 'Return value is a count of pips.'],
```

Argument event types: `ModifierUnitEvent`, `ModifierAbilityEvent`, `ModifierAttackEvent`,
`ModifierInstanceEvent`, `ModifierOverrideAbilitySpecialEvent`, `ModifierAddedEvent`, `ModifierHealEvent`, or `null` for no arguments.

### How to Add Type Declarations

In `build/vscripts/api-types/index.ts`:

```typescript
apiTypesDeclarations.push({
  kind: 'object',
  name: 'MyNewType',
  extend: ['ExistingType'],  // Optional inheritance
  fields: [
    { name: 'fieldName', types: ['float'] },
    { name: 'optionalField', types: ['string', 'nil'], description: 'Field description.' },
  ],
});
```

### How to Add Enum Value Descriptions

In `build/vscripts/enums/data.ts` → `enumValueDescriptions`:

```typescript
export const enumValueDescriptions = {
  EnumName: {
    __self: 'https://link-to-reference',  // Optional enum-level description
    ENUM_MEMBER_NAME: 'Description of this member.',
  },
};
```

### How to Add Panorama Events

In `build/panorama/events/data.ts`:

```typescript
// Add new events
export const additions: Record<string, PanoramaEvent> = {
  EventName: {
    description: '',
    panelEvent: false,
    args: [{ name: 'argName', type: 'string' }],
  },
};

// Override existing event arguments
export const override = (events: Record<string, PanoramaEvent>) => {
  events.EventName.args[0].name = 'newName';
};
```
